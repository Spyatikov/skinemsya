# Бэкап базы «Скинемся»

Каждую ночь в 03:17 по Москве GitHub Actions выгружает все таблицы приложения (схема `public`: группы, участники,
траты, сообщения, профили, статистика), шифрует файл паролем (AES-256) и хранит его 30 дней.
Репозиторий публичный, поэтому без пароля файл бесполезен.

Где смотреть: GitHub → репозиторий → **Actions** → «Ночной бэкап базы». У каждого запуска внизу есть
артефакт `skinemsya-db-ДАТА`, а в отчёте — число строк в каждой таблице.
Если бэкап не удался, GitHub пришлёт письмо на почту аккаунта.

## Настройка (один раз)

1. **Строка подключения.** Supabase → проект skinemsya → кнопка **Connect** вверху → вкладка
   **Session pooler** (не «Direct connection»: у GitHub нет IPv6, прямое подключение не заработает).
   Скопируй строку вида
   `postgresql://postgres.ubpfdbojasicjhcciqjr:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres`
   и подставь пароль базы вместо `[YOUR-PASSWORD]`.
   Если пароль не помнишь — Project Settings → Database → **Reset database password**.
   Сброс пароля ничего в приложении не сломает: сервер работает через отдельный ключ, а не через пароль базы.
2. **Пароль для шифрования.** Придумай длинный пароль (от 12 символов) и сохрани его в менеджере паролей.
   Без него бэкап не расшифровать — восстановить его нельзя.
3. **Секреты в GitHub.** Репозиторий → Settings → Secrets and variables → Actions → **New repository secret**:
   - `SUPABASE_DB_URL` — строка из шага 1;
   - `BACKUP_PASSWORD` — пароль из шага 2.
4. **Проверка.** Actions → «Ночной бэкап базы» → **Run workflow**. Через пару минут должна появиться зелёная галочка
   и артефакт.

## Как восстановить

Нужен установленный PostgreSQL 17 (`pg_restore`) и `gpg`.

```bash
# 1. Скачать артефакт из Actions и распаковать zip, затем расшифровать:
gpg --decrypt skinemsya_2026-10-29_0317.pgc.gpg > dump.pgc

# 2a. Посмотреть содержимое без восстановления:
pg_restore --list dump.pgc

# 2b. Вытащить одну таблицу в SQL (например, если кто-то случайно удалил траты):
pg_restore --data-only --table=expenses -f expenses.sql dump.pgc

# 2c. Полностью восстановить в базу (ОСТОРОЖНО: --clean удаляет текущие таблицы public и создаёт заново):
pg_restore --clean --if-exists --no-owner --no-privileges -d "СТРОКА_ПОДКЛЮЧЕНИЯ" dump.pgc
```

Для полного переезда на новый проект Supabase: создать проект, применить миграции из `supabase/migrations`
(в них есть расписание напоминаний и функции статистики), затем восстановить данные командой 2c
и задеплоить функцию `supabase/functions/api`.

## Что не входит в бэкап

- Секреты функций (токен бота, ключ Anthropic) — они живут только в настройках Supabase.
- Код — он и так в этом репозитории.

## Важно

GitHub отключает расписание в публичных репозиториях, если в репозитории 60 дней не было коммитов.
Тогда в Actions появится кнопка «Enable workflow» — её достаточно нажать.
